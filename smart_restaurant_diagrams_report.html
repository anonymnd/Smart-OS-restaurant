2. MLD - Modèle Logique de Données

Le MLD traduit le modèle conceptuel en tables relationnelles exploitables dans SQLite ou PostgreSQL.

RESTAURANT(id PK, nom, adresse) ZONE(id PK, restaurant_id FK -> RESTAURANT.id, nom, type) TABLE_RESTAURANT(id PK, zone_id FK -> ZONE.id, capacite, position_x, position_y, etat, client_id FK -> CLIENT.id NULL) CLIENT(id PK, taille_groupe, heure_arrivee, table_id FK -> TABLE_RESTAURANT.id NULL, statut, temps_attente) PERSONNEL(id PK, nom, role, position_x, position_y, statut, tache_actuelle_id FK -> TACHE.id NULL) CAMERA(id PK, nom, zone_id FK -> ZONE.id, flux_video, statut) CAPTEUR(id PK, type, zone_id FK -> ZONE.id, statut) EVENEMENT(id PK, type, source, confiance, date_event, client_id FK -> CLIENT.id NULL, table_id FK -> TABLE_RESTAURANT.id NULL, personnel_id FK -> PERSONNEL.id NULL, camera_id FK -> CAMERA.id NULL, payload_json) COMMANDE(id PK, client_id FK -> CLIENT.id, table_id FK -> TABLE_RESTAURANT.id, statut, date_creation, date_modification) ARTICLE_COMMANDE(id PK, commande_id FK -> COMMANDE.id, nom, quantite) TACHE(id PK, type, table_id FK -> TABLE_RESTAURANT.id NULL, client_id FK -> CLIENT.id NULL, personnel_id FK -> PERSONNEL.id NULL, score_priorite, niveau_priorite, statut, explication, date_creation) DECISION_AI(id PK, tache_id FK -> TACHE.id, evenement_id FK -> EVENEMENT.id NULL, score_priorite, explication, date_decision)

4. Diagramme d'État d'une Table

Chaque table suit un cycle de vie précis, déclenché par les événements capteurs, caméra ou staff.

stateDiagram-v2
    [*] --> FREE
    FREE --> ARRIVED: Groupe detecte entree
    ARRIVED --> SEATED: Client assis
    SEATED --> WAITING_ORDER: Attente serveur
    WAITING_ORDER --> ORDER_IN_PROGRESS: Commande prise
    ORDER_IN_PROGRESS --> WAITING_FOOD: Envoyee cuisine
    WAITING_FOOD --> SERVED: Plat servi
    SERVED --> FINISHED: Client termine
    FINISHED --> NEEDS_CLEANING: Client quitte
    NEEDS_CLEANING --> FREE: Table nettoyee

Objectif

Éviter les oublis opérationnels: prise de commande tardive, service en retard, table non nettoyée ou file d'attente non traitée.

5. Séquence - Arrivée Client Jusqu'au Service

Le parcours client est suivi depuis l'entrée jusqu'au service de nourriture.

sequenceDiagram
    participant C as Camera entree
    participant B as Backend FastAPI
    participant DT as Digital Twin
    participant AI as Decision Engine
    participant W as Tablette serveur
    participant K as Cuisine
    C->>B: Detecte groupe entrant
    B->>DT: Cree client + statut ARRIVED
    DT->>AI: Envoie etat restaurant
    AI->>AI: Calcule priorite
    AI->>W: Tache: asseoir client
    W->>B: Confirme client assis
    B->>DT: Table = SEATED
    DT->>AI: Nouvel etat
    AI->>W: Tache: prendre commande
    W->>B: Confirme commande prise
    B->>K: Envoie commande cuisine
    B->>DT: Table = WAITING_FOOD
    K->>B: Plat pret
    AI->>W: Tache: servir table
    W->>B: Confirme plat servi
    B->>DT: Table = SERVED
